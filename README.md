# Lantern HR Dashboard (static)

A scoped-down, static clone of five pages from the main Lantern HR Dashboard
Tool — Headcount, Tenure, Attrition (Attrition / Turnover / Voluntary &
Regrettable / Cost of Attrition), Employee Locations, and a basic Q&A People
Assistant — with no backend except a single Vercel serverless function for
the assistant. No database, no upload flow: the anonymized data is baked
directly into the JavaScript bundle at build time, and the whole site is
otherwise static files deployable anywhere, including Vercel's free tier.
This mirrors the pattern used by the sibling `heat-map-dashboard` project.

## Why this exists

The main dashboard (`HR Dashboard Tool`) runs as a Node server with
file-based storage on Render, which needs real hosting/auth work to fix.
This is a lighter-weight subset for Vercel: send an updated data export
periodically, regenerate `src/data.js`, redeploy.

## What's in the data

`src/data.js` (generated by `scripts/build-data.mjs`, or the hand-written
placeholder currently checked in) contains one record per person with
**only**: department, work location, worker category, position status,
contractor flag, job title, annual salary, hire/rehire/termination dates,
termination reason, and voluntary/regrettable flags.

**No names, employee ids, or manager fields are ever present** — not
withheld by the UI, but actually absent from the data file itself.
`scripts/build-data.mjs` strips them from any real export before writing
`src/data.js` (see `IDENTITY_FIELDS` in that script). The five pages
themselves are also written to never show a per-person list — clicking a
department/office/bucket only ever narrows an aggregate count, never reveals
a name. (The main dashboard's Headcount/Tenure/Turnover/Cost of
Attrition/Employee Locations pages all have a people-list drill-down; those
are intentionally removed here — see the "What was simplified" section.)

The currently checked-in `src/data.js` is **hand-written synthetic sample
data** (a few dozen fake records across 8 departments, hire dates spanning
2023–2026, and about a dozen synthetic terminations with reasons/voluntary
flags) so the app is demoable before a real export exists. It is clearly
marked as a placeholder in the file's header comment — regenerate it before
sharing this dashboard for real use.

## Running locally

```bash
npm install
npm run dev
```

Open the printed localhost URL (port 5176). The password is set in
`src/PasswordGate.jsx` (`lantern2026` by default) — **change it** before
sharing the link. Read the comment in that file: this is a speed bump, not
real security. A static site's JS bundle — and therefore whatever is in
`src/data.js` — is downloadable by anyone who has the link, regardless of
the password screen. Don't put anything more sensitive than the aggregate
fields listed above into `src/data.js`.

## Updating the data

When you have a fresh census export, regenerate `src/data.js` instead of
hand-editing it:

```bash
npm install xlsx --no-save
node scripts/build-data.mjs "C:\path\to\Employee Census export.xlsx" ["C:\path\to\Voluntary vs Regrettable workbook.xlsx"]
npm uninstall xlsx
```

The V&R workbook argument is optional — without it, terminations use
whatever voluntary/regrettable/reason data is already on the census rows.

### Expected file format

The census file should have a sheet named **"Employee Census Report"** (any
other sheet name falls back to the first sheet in the workbook). Columns are
matched by name similarity (exact, then fuzzy) using the same registry the
main dashboard uses — the columns that matter for this build, with their
recognized synonyms, are:

| Canonical field | Example column names recognized |
|---|---|
| `department` | HOME DEPARTMENT, Department, Dept, Cost Center |
| `location_state` | Worked In State, Work State, State, Home State |
| `work_location` | LOCATION, Work Location, Location Code (ADP codes like `OSDAL - Onsite-Dallas`, `R-TX - Remote-Texas`) |
| `worker_category` | Worker Category, EE Type, Employee Type, Pay Type |
| `position_status` | Position Status, Status, Employment Status (Active/Leave/Terminated) |
| `role` | Job Title, Role, Position, Title |
| `annual_salary` | Annual Salary, Salary, Annual Rate |
| `hire_date` | Hire Date, Start Date, Date of Hire |
| `rehire_date` | Rehire Date, Most Recent Hire Date |
| `termination_date` | Termination Date, Term Date, Separation Date |
| `termination_reason` | Termination Reason, Term Reason, Reason |
| `voluntary_flag` | Voluntary, Vol/Invol, Voluntary vs Involuntary |
| `regrettable_flag` | Regrettable, Regrettable vs Non Regrettable |

The export can (and normally will) also carry ASSOCIATE ID, EMPLOYEE NAME,
MANAGER, etc. — those are read only so the script's logic can run, then
**stripped** before `src/data.js` is written; they are never persisted.

The optional V&R workbook is matched the same way, expecting FIRST NAME/LAST
NAME (used only to join, then discarded), SEPARATION DATE, SEPARATION TYPE
(Voluntary/Involuntary/Layoff/Contract Ended/Did Not Start), and REGRETTABLE
(Yes/No/New Hire) columns, on a sheet named "Separations 2026" (or the first
sheet).

See `scripts/mapping/registry.js` for the complete, authoritative synonym
lists (it's a verbatim copy of the same file the main dashboard uses).

## People Assistant / serverless function

`api/assistant.mjs` is a Vercel serverless function (Node runtime) that
holds `ANTHROPIC_API_KEY` server-side and answers questions about the baked-in
aggregate data (headcount, attrition, terminations, work locations) using a
small tool-calling loop against the Anthropic API (model: `claude-sonnet-5`).
It is Q&A only — no conversation logging, no self-improving eval loop, no
admin guidance page (those need persistent storage this serverless function
doesn't have).

For local development, either:
- Run `vercel dev` (which serves both the Vite app and `/api/assistant`), with
  a `.env` file (copy `.env.example`) providing `ANTHROPIC_API_KEY`, or
- Just use `npm run dev` for the 5 dashboard pages — the assistant tab will
  show a "not configured" error until you also run `vercel dev` or deploy.

## Deploying to Vercel

1. Push this folder to its own GitHub repo (see below).
2. On [vercel.com](https://vercel.com), **Add New → Project**, import that
   repo. Vercel auto-detects Vite for the static site and `api/assistant.mjs`
   as a serverless function — no extra configuration needed.
3. In the Vercel project's **Settings → Environment Variables**, add
   `ANTHROPIC_API_KEY` with a real key. Without this, the dashboard pages
   still work; only the People Assistant tab will show a "not configured"
   error.
4. Deploy. You'll get a `*.vercel.app` link you can send around.
5. Change the password in `src/PasswordGate.jsx` before your first deploy.

## What's in scope / out of scope

**In scope:** Headcount, Tenure, Attrition, Turnover, Voluntary &
Regrettable, Cost of Attrition, Employee Locations, and a basic People
Assistant chatbot.

**Explicitly out of scope** (not ported): Compensation (Pay Changes,
Headcount Budget), Onboarding, Equipment, Applicants, New Hires, any
admin/upload UI, the People Assistant's self-improving eval loop and
operator-guidance admin page, and session/SSO auth (this uses the same
simple password-gate pattern as `heat-map-dashboard` instead).

## What was simplified for privacy

Every page that shows a per-person drill-down in the main dashboard has had
that drill-down either removed or reduced to aggregate counts here, since a
static bundle's data is extractable by anyone with the link:

- **Headcount**: clicking a row opens a second aggregate breakdown by
  another dimension, not a table of individual people.
- **Tenure**: clicking a department scopes the KPIs/bands/chart; the main
  repo's per-person table (name, title, dates) is removed.
- **Turnover**: the Manager filter and the by-name termination list are
  removed (there is no manager field in this build's data at all); clicking
  a reason just shows its count.
- **Cost of Attrition**: the "manager" group-by dimension and the per-person
  write-off table are removed; clicking a bucket/group only narrows the
  aggregate $ total shown.
- **Employee Locations**: the `PeopleList` click-to-reveal-names component is
  removed entirely — office/remote breakdowns are static aggregate bars only.
